# Embodiment

Giving the connectome a body, a world, and a closed sensorimotor loop.

---

## 1. The body model

**PROVENANCE: MODELED REFERENCE ANATOMY.** Not the Fish1 specimen, not a scan of
any animal.

### Why modelled rather than sourced

No openly redistributable whole-body 6–7 dpf zebrafish surface mesh was found:

| Source | What it offers | Why not used |
|---|---|---|
| [mapZebrain](https://mapzebrain.org/) | Expert-annotated brain regions, >4,000 single-neuron morphologies, 6 dpf reference | **CC-BY-NC 4.0.** The NonCommercial term would encumber this whole project, and it is a *brain* atlas — no external body surface. |
| [FishExplorer](https://fishexplorer.zib.de/) | Shared anatomical space; documents mapping Fish1 into mapZebrain | Documents registration workflows; does not publish body geometry. |
| Fish1 release | EM volume, segmentation, soma, synapses | No external body surface. |

So the body is generated by `src/body/larva.ts` and labelled honestly
everywhere it appears. Rather than block embodiment on an asset, we built one
and told the truth about it. If a redistributable body is obtained later, the
build step converts it into the same container and nothing downstream changes.

### What makes it read as a larva, not a small adult

- **Very large eyes** (~168 µm diameter) relative to the head
- **A single continuous median fin fold**, not separate dorsal/anal fins —
  produced by pinching the cross-section toward a blade posteriorly
- **A ventral yolk-sac extension** still present behind the head
- **A laterally compressed trunk** tapering to a narrow caudal peduncle
- Blunt snout, no adult body depth or barbels
- Head wide enough (~300 µm) to actually contain the measured brain region

Built as a lofted surface over ~20 profile control points, smoothstep-blended,
plus two eye ellipsoids. **3,276 vertices, 6,400 triangles, 10 bones, 180 KB.**
Deterministic: the same options always produce byte-identical geometry.

## 2. Mesh pipeline

glTF/GLB is fine as an *authoring* format; the runtime never parses one.
`npm run build:body` runs the TypeScript generator under Node and emits:

```
public/body/manifest.json
public/body/v1/larva.meshbin      MSH1 container
```

The `MSH1` format mirrors the neuron index (`CLN1`): magic, JSON descriptor,
8-byte-aligned lanes for positions / normals / bone indices / bone weights /
indices. Self-describing, zero-copy, versioned, and validated on read — indices
are re-checked against the vertex count so a tampered or truncated file cannot
hand the GPU out-of-range memory.

The artifact is round-tripped through the decoder at build time; a mesh that
fails validation never ships.

## 3. Renderer integration

No Three.js. Indexed triangle meshes were added to the existing WebGPU and
WebGL2 backends as a peer of the soma layer:

| | WebGPU | WebGL2 |
|---|---|---|
| Skinning | 2 bones/vertex in the vertex shader | same |
| Per-draw uniforms | dynamic-offset uniform buffer, 1280 B slots | `uniform` calls |
| Translucency | one blend pipeline, `cullMode: none`, depth writes off | back faces then front faces, depth writes off |
| Clipping | 4 half-space planes, in-shader discard | same |

**Ordering.** Opaque/occluding surfaces draw *before* the soma so they can depth-
reject hidden neurons; translucent surfaces draw *after*, with depth writes
disabled, so the neurons inside show through. That is the whole point of ghost
and tissue modes.

Transparency is deliberately not order-independent: a depth-prepass or OIT is
real cost, and for a body this convex, two ordered passes are close to correct.

**The depth cue is scale-invariant.** Haze is computed relative to the camera's
own orbit distance. An absolute cue (Phase 1) crushed the whole population to
near-black the moment the camera pulled out to whole-animal scale.

## 4. The rig

One rigid head bone plus a chain of 9 spine bones with lengths growing toward
the tail.

```
M_i = M_parent · T(head_i) · RotY(θ_i) · T(−head_i)
```

Rotating about each bone's own rest head keeps joints anchored; inheriting the
parent's matrix makes curvature accumulate, so the tail sweeps far more than the
trunk from the same per-bone angle. That is anguilliform swimming.

**The head never bends** (`boneAngles[0] === 0`, asserted by test). Brain tissue
and the eyes are bound rigidly to bone 0, so the measured connectome is never
deformed by locomotion.

Tail kinematics are a travelling wave with a quadratic amplitude envelope. A
*bias* term added to the wave is what produces turns — real larval turns come
from an asymmetric beat, not from rotating the animal directly. The resulting
pose asymmetry then feeds back into yaw, so turning follows from how the tail is
actually shaped.

## 5. Locomotion

Larval zebrafish swim in discrete **bouts** separated by passive **glides**, and
at their Reynolds number drag bleeds off speed in a few hundred milliseconds.

| Parameter | Value | Rationale |
|---|---|---|
| Forward bout | 200 ms, 28 Hz beat | published larval slow-swim range |
| Turn bout | 160 ms, 24 Hz, biased beat | routine turns |
| Escape | 120 ms, 52 Hz, high amplitude | C-start-like |
| Bout envelope | `sin(πt)` | bouts ramp and decay, not switch on |
| Linear drag | 6.2 /s | ~160 ms velocity time constant |
| Peak speed | ~15 mm/s forward (~4 BL/s), ~40 mm/s escape | larval kinematics |
| Inter-bout | ~1.15 s, modulated by arousal | spontaneous swimming |

**PROVENANCE: SIMULATED.** A plausible model tuned to published ranges, not a fit
to any dataset, and not driven by Fish1.

### A bug worth recording

The first tuning produced a runaway: swimming toward a stationary object makes
it expand, the loom cue crossed a low threshold, the animal startled, which made
it approach faster, which raised the loom rate further. The fish ended up
permanently escaping at 38 mm/s. Fixed by raising the threshold to 2.5 rad/s,
gating on a minimum angular size, and adding a 3 s refractory period — which is
also how real escape systems behave.

## 6. The loop

```
WORLD ──▶ SENSORS ──▶ CONTROLLER ──▶ MOTOR ──▶ BODY ──▶ WORLD
  ▲                                                        │
  └────────────────────────────────────────────────────────┘
```

Each stage is a separate interface (`src/embodiment/types.ts`). There is no
`FishAI` god-class, because the entire point is that the controller can later be
replaced by a neural readout without touching the body, the world, or the UI.

### Rates

| Stage | Rate | Why |
|---|---|---|
| Render | rAF | whatever the compositor gives |
| Physics | **120 Hz fixed** | reproducible; frame rate must not change the simulation |
| Behaviour | **15 Hz fixed** | larval decisions happen at bout frequency, not per millisecond |

A 0.25 s clamp stops a backgrounded tab from simulating a burst of hundreds of
steps on return. Real elapsed time is *not* clamped — only the simulation — so
the organism's reported age never drifts behind the wall clock.

Determinism: a given seed plus a given input sequence reproduces the same
behaviour, asserted by test. Without it, benchmarks are noise.

### Sensing

`SIMULATED SENSOR INPUT`, and explicitly a proxy rather than a retina: bearings,
angular sizes, luminance, flow and contact instead of pixels. The one quantity
worth getting right now is the **loom rate** (d(angular size)/dt), because it is
the cue that drives real escape responses and it is what a looming-threat
experiment will drive.

### Acting

`MotorCommand` is deliberately tiny and physical — `forwardDrive`, `turnDrive`,
`startleDrive`. A neural controller must be able to produce exactly this from
population readouts with nothing policy-shaped left over.

## 7. What this is not

- **Fish1 does not drive the motion.** The UI badges `SIMULATED BODY MOTION` and
  `CONNECTOME COUPLING OFF` in the viewport, every frame.
- **Drives are not feelings.** `threatEstimate: 0.42` means a number in this
  program is 0.42. It says nothing about any animal. Shown under
  `AGENT STATE — SIMULATED`.
- **There is no consciousness claim anywhere**, and no field for a
  natural-language "thought".

## 8. Design lessons taken from embodied-zebrafish work

Work on embodied larval zebrafish simulation (commonly discussed as *simZFish*)
establishes the architecture we are building toward: neural circuits coupled to
body mechanics, a sensory environment, visual feedback, motor output, and
environment dynamics, in a closed loop. We are not copying an implementation;
we are taking it as evidence that this is a valid direction and letting it shape
the seams:

1. **The body is part of the computation.** Drag, bout structure and tail
   mechanics determine what a motor command actually achieves, so they are
   modelled explicitly rather than abstracted into "velocity".
2. **Sensing must be replaceable.** A coarse proxy today, a retinal encoder
   later, behind one interface.
3. **Closed loop or nothing.** Actions must change future observations, or the
   controller is being evaluated on a recording.
4. **Fixed timesteps.** Coupled neural/body/environment systems are not
   reproducible on a variable render clock.
